## Acceptance Checklist (enforced) — `KG-ISF-COMPLETENESS.5.xi.a` (CODE) — DONE `2026-09-22`

- [x] **ROOT CAUSE (WHY + WHERE)** — `parse_encoding_numeric_literal` (`crates/specforge/src/ir/evidence.rs:6595`) tries `trimmed.parse::<u32>()` BEFORE its all-`0`/`1` arm, so the binary arm is reachable only when the decimal parse overflows `u32` — never below eleven digits. The radix is therefore a function of the string's LENGTH with a discontinuity at 11 characters: a bare `0010` reads as **10** where CCIX states `MsgType[3:0] = 0010`, i.e. **2**. Diagnosed by replaying the producer per table and attributing each minted member to its row (`.5.xi`): **336 minted member values read this way, 92 with a leading zero and 244 bare**, across 27 documents and 64 enums. **Worse than a fabrication**: `.5.vii`'s census flags a fabricated ordinal, whereas a mis-radixed cell publishes a number that LOOKS document-stated and no census questions it.
- [x] **ADDRESSED (verified, measured per item)** — `parse_encoding_member_value` reads the cell in the radix the TABLE states, decided by content shape only (ADR 0006): a zero-padded all-`0`/`1` sibling in the same column **at the same width** or in the same **ROW** carries a bare cell to binary; a same-width digit `>= 2` refutes it and outranks it; absent a witness the cell keeps today's decimal reading. Measured per slot over all 336: **198 binary / 133 decimal / 0 zero-padded-decimal / 5 undecidable**. **Cross-checked against the tracked mirror the `.5.viii` way** — the three decision functions extracted VERBATIM from `evidence.rs` into a standalone harness and run over all **336 slots with their full column and row context: `rust_binary=198, mismatches=0`.** Width stratification and the row witness are both load-bearing and both pinned by tests: `opencapi_4_0 table_0092` fuses a width-1 bit-index table with a width-4 encode table in one column, and the Cortex-A76 row `op0|op1|CRn|CRm|op2` = `11|011|0100|0100|000` puts the only evidence in the siblings (17 of the 22 slots a column-only rule cannot decide). All 18 contestable calls and all 5 residual slots were read by hand against their source documents in `.5.xi`.
- [x] **NO REGRESSION** — **`evidence --dry-run` over every persisted `source_ir.json` with BOTH binaries: 27 replayed / 51 refused as schema-1, and all 27 `cmp` BYTE-IDENTICAL.** That is the PREDICTED result, not a no-op: `.5.xi` measured the replayable reach of this defect at **0** (attribution-free upper bound also 0), because the replayable corpus states its codes as `0b`/`0x` literals (94 + 4 of 126 matches) or single digits (28), which are radix-invariant. **WIRE-BASED-100 = 1.000 holds by construction**: the three rebuildable AMBA wire golds (`ihi0022_l` AXI, `ihi0024_e` APB, `ihi0033_c` AHB) are inside those 27 and their evidence is byte-identical, so the scorer's input cannot have moved. `kg-bench` **156/156**. `cargo fmt --all -- --check` clean; `cargo clippy --offline --all-targets -- -D warnings` clean; `cargo test --workspace --lib --exclude specforge-production-graph` green — specforge **473**, conformance **168**, core **1,618** (+12 tests).
- [x] **NON-ADDITIVE AT THE IDENTITY SEAMS (proved, not placed)** — `.5.viii` had to be confined to the member seam because widening the shared reader would have moved `derive_header_sourced_enum_name` clause 5, and a table that starts PARSING starts NAMING an enum. This leaf has no such exposure and the reason is structural: for an all-`0`/`1` digit string the decimal arm succeeds only at ten digits or fewer, where the binary reading is at most 1023 and cannot overflow, and above ten digits the decimal arm already fails and the binary arm already runs. **The set of cells that PARSE is identical under either ordering — only the value changes.** Verified over all **71,001** distinct trimmed corpus cells: **0** divergences; `decimal_before_binary_is_parse_success_invariant` pins the property over widths 1–40 and `the_unquoted_radix_stays_out_of_the_enum_identity_seams` pins the two seams themselves.
- [x] **GENERICITY (ADR 0006)** — the rule reads no header word, no vocabulary and no document key. It asks only what shape the publisher wrote: does a cell of this width in this column or this row carry a leading zero, and does a cell of this width carry a digit above `1`. The rejected alternative is on record in `.5.xi`: an unstratified `digit >= 2` test refutes the binary reading of `opencapi_4_0 table_0092`, whose bit indices and encodes share one column at different widths.
- [x] **LOCKSTEP** — `.5.xi.a` closed with its measured numbers; report `docs/research/decimal-before-binary-encoding-values.md` §LANDED; KM card `[[decimal-before-binary-needs-a-notational-witness]]` re-pointed from *"the repair is owned by `.5.xi.a`"* to the shipped rule with its `reverify` re-derived; book `pipeline/isf-adapter.md` rewritten from "this limit is tracked separately" to the shipped reading; tree root frontier; `MEMORY.md`. **`CHANGES.md` and `LIVE_ACHIEVEMENT_STATUS.md` deliberately unchanged**: no product-status figure moves, because every affected value is in the legacy stratum and the current pipeline's output is byte-identical — what changed is what the NEXT refresh will import.

## Acceptance Checklist (enforced) — `KG-ISF-COMPLETENESS.5.xiv.a` (CODE) — DONE `2026-09-22`

- [x] **ROOT CAUSE (WHY + WHERE)** — `build_symbol_definitions` (`crates/specforge/src/ir/semantic.rs:4231`) already drops a member NAME carrying two different values (`conflicting_value`), but never checked the mirror: one VALUE carried by two different NAMES. `.5.v`'s standing rule is that no encoding assigns one code to two members, so a collision is provably wrong and needs no interpretation. Measured by `.5.xiv`: **266 colliding enums corpus-wide, 9 replayable, 8 of them crossing into IntentIR `symbol_definitions`** — the boundary `README.md` declares — with `HPROT` colliding on 6 of 8 members, `HSIZE` on 4 of 6, `AWSNOOP`/`BTAGMATCH` on 5. - [x] **THE ORACLE LANDED WITH THE GATE, AND IT IS RED-VERIFIED** — `.5.xiv` measured that **no oracle in this repository could see an enum member value**: 0 of 156 `kg-bench` fixtures mentioned `enum` or `symbol_definition`, and `eval-extraction`'s nine task kinds contain none. The fixture schema could not express one either, so `CanonicalStageExpectations` gains `symbol_members_include` (symbol/member/value) and `symbol_names_exclude` (the HOLD-OUT side — a passing state that is an ABSENCE, which no `_include` can express). New fixture `enum_code_collision_holdout_gold` carries a colliding split-bit table beside a clean one. **Proven RED: with the gate stashed it FAILS** — `expected symbol_names_exclude to exclude TSIZE, but actual set was {"TBURST", "TSIZE"}` at both `semantic` and `intent` — **and passes with it**, while `TBURST` survives in both directions, so the gate is proven not to over-reach.
- [x] **ADDRESSED (verified, measured per MEMBER)** — `semantic --dry-run` over every persisted `evidence_ir.json` with BOTH binaries: 27 built / 51 refused as schema-1. Per-member diff of `symbol_definitions`: **40 member values withdrawn across 8 symbols in 2 documents — `HPROT` (6, withdrawn entirely), `HSIZE` (4, withdrawn), `SYSCOACK` (4, withdrawn), `BTAGMATCH` (−8), `AWSNOOP` (−7), `ARSNOOP` (−5), `ARCACHE` (−4), `AWATOP` (−2) — and 0 members or symbols GAINED**, which is the required direction for a subtractive rule. The colliding GROUP is dropped rather than the whole enum, at the granularity of the rule it mirrors: that keeps `AWATOP`'s nine correct members and `ARCACHE`'s six, where dropping the enum would have discarded them, and dropping one side of a pair would have picked a winner — the fabrication `.5.vii.a` removed.
- [x] **NO REGRESSION** — `kg-bench` **157/157** (156 + the new fixture). **WIRE-BASED-100 = 1.000 holds, and it is DERIVED rather than argued**: across all 27 rebuilt SemanticIR artifacts the only fields that move are `symbol_definitions` (2 documents) and `proof_ledger` (the same 2, which must move when the artifact does); **every fact surface the scorer reads — interfaces, actor_signal_relations, actor_ports, regular_states, state_transitions, temporal_rules — is byte-identical in all 27**, so the scorer's input cannot have moved. `cargo fmt --all -- --check` clean; `cargo clippy --offline --all-targets -- -D warnings` clean (it caught a test call site the production build did not, exactly as `COMMIT-GATE-SINGLE-RUN.9` records); `cargo test --workspace --lib --exclude specforge-production-graph` green — specforge **473**, conformance **168**, core **1,620** (+2 seam tests).
- [x] **AN EMPTIED ENUM IS NOT PUBLISHED** — both per-member rules can now empty an enum, and emitting the husk would publish a symbol that states nothing while looking like a definition. `build_symbol_definitions` therefore `filter_map`s an enum with no surviving member out entirely, which is the same outcome `.5.ii`'s spine gate and `.5.iii`'s `_WIDTH` gate already produce at the statement seam.
