# API Reference

The book explains what SpecForge does and why. The API reference documents the Rust types and functions
that do it, generated by rustdoc from the code's own doc comments.

## Where it is

`cargo xtask docs` (or its shim, `scripts/run_docs_ci.sh`) builds the book into `generated/mdbook/specforge/`
and the rustdoc of every workspace crate beside it, in `generated/mdbook/specforge/api/`. From the built book:

- [`specforge_core`](../api/specforge_core/index.html) is the library and the place to start. Its `ir`
  module holds the staged representations (`ir::source`, `ir::evidence`, `ir::semantic`, `ir::intent`)
  and the adapters (`ir::adapters`, `ir::isf_ir`). It is the production boundary: it may encode universal
  document grammar and digital-design semantics, and nothing from a named document.
- [`specforge`](../api/specforge/index.html) is the command-line tool and a compatibility facade over
  the two library crates.
- [`specforge_conformance`](../api/specforge_conformance/index.html) is the downstream evaluation,
  replay and fixture plane. It may depend on `specforge_core`; the reverse is forbidden.
- [`specforge_production_graph`](../api/specforge_production_graph/index.html) is the tool behind the
  production-genericity census and its information-flow check.

These links resolve in the built book. A copy of this page read anywhere else has no `api/` beside it.

## Building it on its own

```bash
cargo doc --offline --workspace --no-deps --open
```

The `ir` sources live under `crates/specforge/src/ir/` and compile into `specforge_core` through
`#[path]`, so their documentation appears under `specforge_core::ir`.

## Kept buildable

The `RUSTDOC` doctrine ([Doctrine Enforcement](doctrine-enforcement.md)) runs the same build under
`-D warnings` at every commit, so a doc comment rustdoc cannot resolve is refused when it is written.
How much of the public surface carries documentation is measured rather than required
(`RUSTDOC-AND-XTASK.7`).
